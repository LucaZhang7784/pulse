# Pulse UI Design · 设计提案

2026-10-10 · 推荐 A / Graphite Signal。此目录是设计探索，尚未替换应用界面。所有预览数值、模型名、时间与套餐都是演示内容。

## 1. 观察与设计问题

从 `../main.js` 与 `../renderer/style.css` 观察，当前悬浮栏宽 55px、详情窗 280×360px；透明深色外壳、圆环与细小文字承担主要信息。`../renderer/card.js` 的详情同时包含账户额度与会话信息。设计方法参考本目录 Skills_Review.md 所列本机 skills。这些是本轮的项目证据与设计依据，不是用户可用性研究结论。

先从四个视角提问：

| 视角 | 设计问题 |
|---|---|
| 常驻工具使用者 | 能否一眼识别哪个服务额度紧张？主数字表示已用还是剩余？ |
| 信息准确性 | 模型属于哪个会话？tokens 是最近一轮、单次生成还是整个会话？ |
| 桌面交互与可访问性 | 浮层会不会挡住工作？键盘如何打开和关闭？明亮背景下能否读清？ |
| 视觉与实现 | 如何建立层次又保持安静？哪些材质能用现有 Electron 实现？ |

缺失证据：尚无真实用户访谈、屏幕阅读器验证、不同显示缩放与桌面背景的运行评估。因此下文尺寸和交互为设计建议。

## 2. 三个方向

| 方向 | 视觉方法 | 优点 / 取舍 | 预览 |
|---|---|---|---|
| A · Graphite Signal（推荐） | 石墨黑、青色信号、双层边界、内嵌会话面板 | 安静而有科技感；需要保持小字号对比度 | graphite.png / graphite-antigravity.png |
| B · Frosted Titanium | 钛银、低饱和冷灰、深色正文、轻阴影 | 日间清晰；白色桌面上更依赖边界分离 | light.png |
| C · Precision Console | 冷蓝、等宽数字、细分段进度条、较硬的圆角 | 仪表秩序最强；亲和感略低 | console.png |

推荐 A 为默认，B 可作为浅色主题。C 作为偏好方案；无需同时实现三套不同交互。科技感由精准对齐、清楚的单位、数据来源与更新时间建立；避免无数据依据的走势、装饰雷达与持续闪烁。

## 3. 信息架构与浮层

保持顺序：ChatGPT / Codex → Antigravity → Claude Code → OpenRouter (Claude Code) → DeepSeek → Kimi → MiMo。图标使用项目现有 SVG，不重新生成品牌标志。

推荐悬浮栏 72px 宽、图标按钮约 56×70px；详情面板 360px 宽、内容驱动高度。预览是 1440×960 的提案画板，面板按 CSS 像素绘制，尚未验证实际 DPI。小工作区用最大高度和内部滚动，不允许详情窗溢出屏幕工作区。

详情分四层：

1. 服务、套餐、连接状态、固定与关闭控件。
2. 账户额度：统一“已用”，大数字 + 进度条 + 剩余比例 + 重置时间。
3. 第二额度窗口：周额度单独列出；余额类改为金额与币种，不能复用百分比假装有额度上限。
4. 最近活跃会话：模型、强度、会话时间、明确作用域的 tokens、来源与更新时间。

现有数据来自最近更新的会话记录，不足以证明它是前台窗口正在使用的会话。建议使用“最近活跃会话”，后续有可靠会话定位时再改“当前会话”。Codex 的最近一轮 tokens、Antigravity 的最近一次生成 tokens 不写成会话累计用量；拿不到值显示“未提供”，不显示假零。模型名长时允许换行，完整值可复制。

设计稿可点击各 provider 切换标题；前三种主题可切换。非 Codex / Antigravity 的面板仅演示框架，账户额度和 tokens 未按服务逐一模拟，不能作为其功能规范。固定、关闭、刷新是位置示意，未连接生产逻辑。

## 4. 视觉 tokens（A）

| Token | 建议值 / 用途 |
|---|---|
| Base / Surface / Inset | #0C1016 / #171E27 / #111821 |
| Primary / Secondary text | #EDF4FA / #A0B0BF |
| Signal / Border | #76E4D5 / #354250 |
| Caution / Error | #F2BD70 / #F38A91，辅以文字或图形，不只用颜色 |
| Radius | 外壳 24 / 内层 15 / 控件 8–13px |
| Spacing | 4 / 8 / 12 / 16 / 24px |
| Type | Segoe UI Variable → Segoe UI → Microsoft YaHei；数字 Cascadia Code → Consolas |
| Size | 正文 13–14、辅助 12、主数字 44–52px；预览脚注 10px 仅为提案注释，生产说明建议至少 12px |

表面使用足够不透明的填充保证背景适应性。浅阴影分离桌面，1px 边框分离外壳，内层深色表达会话归属。预览没有实现原生 Acrylic/Mica；CSS 透明和 blur 也不能直接当作真实 Windows 桌面材质。

## 5. 交互与状态建议

- 默认悬停预览，点击固定；Esc 关闭。固定状态采用可辨识图标与文本提示。当前版本以 hover 触发，以上是待实现建议。
- 保留 alwaysOnTop。浮层跨 rail 的移动间隙需延迟关闭；不抢应用输入焦点。键盘操作打开后要有独立的可聚焦路径，不能把 nonfocusable 与键盘需求同时硬套。
- 状态覆盖加载、需登录、程序未运行、数据过期、网络失败、自定义代理、无会话。数据过期可保留上次数值，同时显示更新时间与“过期”；缺失值用破折号和原因。
- 已用接近阈值时采用文字 + 琥珀色，不把高用量画成成功绿；余额不擅自定义警戒线。
- 小于约 120ms 的淡入/位移只在用户操作时播放；支持减少动态效果。不做持续呼吸光、旋转背景或实时装饰粒子。
- 可访问性目标：键盘顺序、可见焦点、完整服务名、非颜色状态提示、系统高对比适配。尚未做完整可访问性评估，不能据此声称达标。

## 6. 实现范围与审查

优先在现有 `renderer/style.css`、`renderer/card.html`、`renderer/card.js` 与 `main.js` 窗口尺寸逻辑实施。不引入前端框架、不增加依赖。数据层先核对 tokens 作用域与更新时间，再写显示标签。浮层布局必须随显示器工作区、左右停靠与缩放自适应。

反向审查：扩大栏宽会占更多桌面空间，可保留紧凑模式；高级材质不能牺牲可读性；不确定会话不可伪装为当前会话；长模型名、金额币种、错误提示需要真实数据验证。生产落地前应审核这些状态和显示缩放。
